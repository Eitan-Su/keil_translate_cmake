# 转换性能记录

记录日期：2026-11-08。

## 第一轮算法调整

源文件对应关系在每次生成时建立一次索引，替代逐文件遍历全部输入的处理。
文件规范化结果只在本次处理期间复用，保留首个匹配来源以及文件级设置的优先顺序。
再次生成时重新建立索引，避免沿用过期的文件信息。

注释和字面量扫描改为定位片段边界，再批量替换片段内容，保留字符位置和 CR、LF 换行。
扫描继续支持 C++ 原始字符串、转义引号、注释续行以及未闭合的输入。
缺少相关特征的源码提前结束对应兼容检查，浮点格式化输入输出检查合并为一次扫描。

普通 ASCII 源文件先完成兼容检查，仅在内容需要转换或目录包含非 ASCII 字符时创建副本，
减少复制后立即删除文件的操作。原始工程源码继续作为只读输入。

## 第一轮测量结果

使用同一台 Windows 机器、Python 3.13.12 和相同 Keil 输入工程，分别运行独立进程。
计时区间为 `generate_cmake()`，包含 GCC 工程、兼容文件和 VS Code 配置生成。
XML 解析、界面初始化和 CMake 编译验证时间单独统计。

下表采用优化前一次采样和优化后三次采样；优化后的代表值为中位数。
这些运行均关闭 `cProfile`，避免函数调用统计影响计时。

| 工程 | 源文件数 | 优化前 | 优化后三次范围 | 优化后中位数 | 耗时比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| N32WB_HID，N32WB03x | 42 | 9.04 秒 | 3.73–4.33 秒 | 4.05 秒 | 2.23 |
| AT32F435RGT7_SDIO，X-Track | 361 | 224.69 秒 | 17.39–18.80 秒 | 17.45 秒 | 12.88 |

耗时比为优化前耗时除以优化后中位数。文件系统缓存和系统负载会影响单次结果，
上述数字仅代表这两个样本的本机测量。

内存通过 Windows `GetProcessMemoryInfo` 记录。在转换核心均从字节码加载的测量中，
42 文件样本的峰值私有内存从 19.42 MiB 变为 19.90 MiB，361 文件样本从
72.23 MiB 变为 72.42 MiB，变化较小。本次优化的主要收益体现为转换耗时下降。

## 第二轮算法调整

文件位置解析结果在单次生成期间复用，减少对同一文件反复调用 `Path.resolve()`。
输出目录清理完成后才启用缓存，生成成功或发生异常时均释放缓存。

源码读取后提取堆分配、浮点输入输出、内嵌汇编、迁移检查和函数声明等摘要。
后续检查复用摘要，缓存中保留布尔值和符号等信息，源码全文在当前文件处理结束后释放。
原始源码与转换副本分别缓存，生成文件重新写入时使对应摘要失效。
再次生成时重新读取源码，确保源文件修改能够更新生成选项。

C++ 头文件逐个解析，同一次注释和字面量屏蔽结果供声明与类型检查共享。
包含文件查找结果同时按所属目录和包含名称区分，保持本地头文件优先顺序。
兼容头文件扫描对每个文件只读取一次，仍保留重复候选的引用计数和强制包含顺序。
迁移检查逐文件汇总结果，避免将整个工程的源码拼接为大字符串。

每个工程按旧版本、新版本的顺序交替测量三次，以各自中位数进行比较。

## 2026-11-09 GD32 兼容性修复的性能对照

比较对象为 GD32 修复前的工作区快照与修复后代码，均包含此前的 FreeRTOS、SLIB 和
转换算法优化。快照文件的 SHA-256 为
`b5142b1b5c6a92ef99b73e53516551dbabb6fa6a9c90cd5efc6aa03453c4b705`。
本轮修复本身的完整验证见 [GD32 配套验证记录](verified_keil_projects.md)。

### 测量方法

Windows、Python 3.13.12，同一组输入，每次使用独立进程和全新输出目录。
两个转换核心均预先编译为字节码，避免主模块源码编译对峰值内存造成干扰。
计时区间为 `generate_cmake()`，包含 GD32 新模块按需加载、配套检查和文件生成，
不包含 XML 初始解析、GUI、CMake 配置或 GCC 构建，也未启用 VS Code 配置导出。

每个工程先对两个版本各预热一次，再测量五轮；每轮交换版本执行顺序。
预热数据保留在原始记录中，统计表仅采用五轮正式采样。
测量期间未同时运行本任务的编译或单元测试。文件系统缓存、杀毒软件及系统调度
仍可能造成波动，因此同时列出中位数和完整取值范围。

数据包含 Python、转换器及公共测量工具，适合本批修复前后比较，不能与其他测量工具

### 编译产物与运行影响

N32 与 AT32F435 的 29 个和 13 个生成文件，仅统一输出目录表示后内容全部一致。
五个 GD32 代表目标共 176 项原始 C 文件编译结果，其 CPU、优化、宏定义等编译选项保持一致，
对应对象文件的可装载代码和数据段也逐项一致。
修复未降低优化级别，也未给应用主循环或驱动函数插入检查代码。

GD32 启动代码改用官方 GCC 实现，链接时保留原 Keil 内存、栈、堆及固定数据区域，
必要的堆边界符号接入现有有界 `_sbrk` 实现。该部分属于正确性修复。
旧版本的 GD32 固件无法完成链接，无法给出有效的整机运行速度或完整固件大小前后百分比。
本轮执行了 ELF 地址检查和两个内核的启动指令模拟，尚未进行物理开发板时钟周期测量。
31 次新构建均成功生成固件，构建成功所增加的链接和导出步骤也不能与旧版失败耗时
作为等价任务的速度对照。

证据保存在 `.cache/gd32-fix-20261108/`：`benchmark-raw.json` 包含全部 60 次采样，
`benchmark-summary.json` 为中位数和范围，`object-comparison.json` 为对象文件比较，
`firmware-checks.json` 为实际 ELF 检查及启动模拟。目录名称保留任务开始日期。
